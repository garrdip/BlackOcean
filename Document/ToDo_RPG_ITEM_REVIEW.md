### R1. 소모품 효과 시그니처가 비전투에서 동작하지 않는다 — 0-9, 6-2, 6-3, 1-10
- 문서: 효과 메서드를 `ConsumableEffects.<Effect>(ConsumableDef def, TargetObject user, TargetObject target)`로 정의하고, 비전투 `CmdUsePotionOnMap`도 같은 `ServerUseConsumable`로 통합한다.
- 코드: 거점·미로에는 TargetObject가 없다. `GamePlayer.CmdHpRecovery`가 "거점(아바타 없음): GamePlayer HP 직접 회복" 분기를 두는 이유이고, 전투 유닛(`spawnedPlayerList`)은 전투 진입 시 `BattleSpawner.GeneratePlayerUnit`이 만든다. 1-10의 `Heal(value, healer)`도 TargetObject 메서드라 같은 문제다.
- 반영: 효과 인자를 `GamePlayer` 기준으로 두고, 전투 중이면 `M_TurnManager.GetCurrentPlayerTargetObject`로 TargetObject를 찾아 전투 전용 효과(버프·치명 회복)를 보강한다. 받는 회복량 증가는 비전투 회복에도 적용 (Q38).

### R2. "자기 턴 시작 리셋"과 "턴 종료 틱"이 섞여 있다 — 5-9, 2-3(A1)
- 코드: TP 루프는 자기 턴 시작에 `next.target.defense = 0`으로 실드를 지운다. `ApplyTimedDebuffTo`는 대상 **턴 종료** 기준으로 감소하며, 자기 턴 중 부여면 `skipFirstTick`으로 이번 턴 종료를 건너뛴다.
- 반영: 실드는 소진까지 지속(Q37) → 턴 시작 리셋 제거(1-14). 몬스터 방어 행동은 `STAT_DEFENSE` 3턴 버프(A1 확정). 방어 액션 실드만 F4.

### R3. MaxHP·maxResource 델타 방식은 구 세이브 이관과 양립하지 않는다 — 3-8, 3-11, 9-1
- 코드: `ApplyEquipMaxDeltas`가 착탈 시 `MaxHP`/`maxResource`에 델타를 더하고, 세이브는 델타가 더해진 값을 그대로 저장한다. `MaxHP`는 레벨업(`AddMaxHP`, 랜덤 시드 성장)과 스킬트리 HP 노드가 직접 가산한다.
- 문제: 이관 시 EquipDB에서 `MaxHP`/`MaxResource` 컬럼이 사라지면 저장된 최대치에서 구 장비 델타를 되돌릴 근거가 없다.
- → **F2**로 다시 질문.

### R4. 드랍 판정 단위가 완료 기준과 모순된다 — A7, 7-3
- GamePlayer마다 굴리면 싱글은 3명이 각자 굴려 "150% → 1개 확정 + 50%"가 3개 확정 + 50%×3이 된다.
- 반영: 싱글 파티 1회, 멀티 플레이어마다 (Q39). 멀티 단위 F6.

### R5. 1-3 처리 순서와 `DamageToPlayer` 역할 분담이 충돌한다
- ResolveHit 안에 "대상 방어 공식 → 피해 적용"을 두면서 `DamageToPlayer`도 방어 공식을 담당한다고 적어 이중 적용 위험이 있었다. `RedirectToGuardian` 재귀 호출에 보호자 재판정 금지 규칙이 없었다.
- 반영: ResolveHit = 공격 측(명중·회피·r·약점·치명·배율), 피격 함수 = 방어 측(대열·분담·실드·방어 공식·HP·분노). 피격 함수가 실제 피해를 반환. 반격·반사는 별도 HitContext로 2차 판정 (Q27).

### R6~R12
- R6: `IsMagic` 헬퍼를 1-2로 이동. Phase 4 전까지 `MAGIC`·`RESONANCE`를 마법으로.
- R7: 1-4 착수 전 미커밋(SkillDB `FreeAction`·`tpUsedFreeSkillNo`) 선커밋.
- R8: 2-4 점검 목록 보강. `ICHI_ATTACK`은 버프 개편 범위.
- R9: `TotalStrength`는 스탯만, 무기 공격력은 `TotalPhysicalAttack/TotalMagicAttack`. 요구치 비교는 힘 스탯(기본 + `STRENGTH` 옵션)만.
- R10: 소모품 `ValidTarget.NONE` = 자신.
- R11: `saveVersion` 추가, 구 세이브 0 → 1 변환기.
- R12: `Reward_Type.Item` 분기는 3-1에서 비워 두고 7-5에서 채움. Phase 0은 CSV 파일을 바꾸지 않음. Phase 3 완료 기준을 "두 공격력이 각각 합산"으로.

## 3. 추가 확인 질문 (F1~F14) — 「답변」 칸에 적어 주세요

각 질문은 "지금 코드가 어떻게 돼 있고, 무엇을 고르면 되는지"를 예시와 함께 적었다. **굵은 글씨가 제안(기본값)** 이다. 답이 없으면 제안대로 진행한다.
